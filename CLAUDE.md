# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## O que é este projeto

Produto Coringa — gerador de encomendas especiais (croqui) da Madel, reescrito como uma aplicação Next.js sem backend (v1). O sistema PHP anterior foi movido para `legado-php/` e mantido só como referência histórica (ver `legado-php/CLAUDE.md` e `legado-php/DOCUMENTACAO.md`); não é mais executado.

## Comandos

- `npm run dev` — servidor de desenvolvimento
- `npm run build` — build de produção (usado também como verificação de tipos/erros)
- `npm test` — roda toda a suíte de testes (Vitest)
- `npx vitest run <caminho>` — roda um arquivo de teste específico
- `node scripts/migrar-biblioteca.mjs` — script único de bootstrap que migrou as fotos de `legado-php/uploads/`; não precisa rodar de novo. Para adicionar uma nova foto à biblioteca, copie o arquivo para `public/biblioteca/produtos/` e adicione uma entrada em `lib/biblioteca-dados.ts` manualmente.

## Arquitetura

- **Motor de produtos** (`produtos/`): um arquivo por tipo de croqui (`porta-marcenaria.ts`, `porta-especial.ts`, `porta-acm.ts`, `esquadria.ts`, `degrau-patamar-rodape.ts`, `outros.ts`), cada um exportando uma `ConfigProduto` com seus campos. Essa mesma config alimenta o formulário dinâmico (Etapa 3) e a seção de especificações do documento gerado — mudar um campo é editar um lugar só.
- **Wizard** (`app/criar/*`): 5 rotas (`tipo`, `pedido`, `especificacoes`, `imagem`, `revisao`) + `resultado`. Estado central em `lib/wizard-context.tsx` (Context + reducer), tipado em `lib/pedido.ts`, salvo na nuvem a cada "Próximo" (ver "Login e croquis salvos"). Não há mais rascunho em `localStorage`: `lib/wizard-storage.ts` só apaga restos de versões antigas, e o croqui em andamento se recupera em "Meus croquis" (edições feitas desde o último "Próximo" se perdem ao recarregar a página).
- **Biblioteca de imagens**: `lib/biblioteca-dados.ts` (manifesto) + `public/biblioteca/produtos/` (arquivos). Alimentada só via edição de código + deploy — não existe tela de upload/admin nesta v1.
- **Desenho editável** (Revisão): `lib/desenho.ts` (modelo + matemática: mover, redimensionar por alça com lado oposto fixo, girar, espelhar, camadas, histórico), `components/croqui/EditorDesenho.tsx` (conteúdo da barra de ferramentas, atalhos, desfazer/refazer) dentro de `components/ui/BarraFlutuante.tsx` (painel `fixed`, arrastável, que expande/recolhe; a linha principal rola na horizontal com setas via `components/ui/LinhaRolavel.tsx` e a barra inteira pode ser minimizada num botão "Editar"; não há ferramenta de retângulo preenchido separada — é a opção "Preencher" do retângulo) com ícones em `components/ui/Icones.tsx`, `OverlayEdicao.tsx` (camada SVG interativa) e `AreaDesenho.tsx` + `ElementosDesenho.tsx` (renderização estática, usada também no Resultado e na exportação). Todas as coordenadas ficam num espaço lógico fixo de 1000×1150 que **é a própria moldura** do "Desenho da peça especial" (proporção fixa, sem margem interna; as réguas de medida são desenhadas por cima), então os itens podem ficar em qualquer ponto dela e o desenho escala igual na tela e nas exportações. Não use altura dinâmica para o quadro: a moldura teria alturas diferentes na Revisão e na exportação e as posições não bateriam. Imagens coladas (Ctrl+V / botão "Colar imagem") viram `ElementoImagem` em `desenho.elementos` (data URL JPEG comprimida a 1200px por `comprimirImagemComDimensoes`, desenhada como `<image>` dentro do SVG — o `html2canvas` só carrega imagens em SVG se forem data URL). Croquis acima de ~4 MB não salvam na nuvem (aviso na tela): as imagens coladas são o que mais pesa. As ferramentas **Apagar área** e **Borracha** não alteram a imagem: guardam em `desenho.apagamentos` pequenos retângulos ("carimbos", `lib/apagamento.ts`) em coordenadas relativas à imagem (0..1), que acompanham a imagem ao mover/girar/espelhar/redimensionar; `AreaDesenho` gera em memória um PNG com transparência (`aplicarApagamentos`, canvas) e marca o `<img>` com `data-processando` enquanto isso — `capturarDocumentoLargo` espera essa marca sumir antes de exportar. Trocar a imagem ou o tipo descarta os apagamentos. O estado fica em `EstadoPedido.desenho` (`elementos` + posição da imagem + apagamentos) e é salvo no rascunho; trocar o tipo do produto o descarta. A edição só existe na Revisão; o Resultado exibe o desenho já consolidado.
- **Documento final**: `components/croqui/DocumentoCroqui.tsx` reproduz o layout dos formulários físicos da Madel; é usado tanto no preview da Revisão quanto na tela de Resultado. No celular (< 768px) `components/croqui/AjusteCelular.tsx` monta o documento com a largura do computador (1000px) e o reduz com `transform: scale` para caber na tela (o usuário dá zoom com os dedos); no computador não faz nada, e a exportação captura um clone do elemento interno, sem esse ajuste. Exportação em `lib/exportar-pdf.ts` / `lib/exportar-imagem.ts` (html2canvas + jsPDF), disparada por dois botões independentes.
- **Login e croquis salvos** (`lib/servidor/*`, `proxy.ts`): banco Postgres da Neon acessado direto por `lib/servidor/banco.ts` (`consultar`; nos testes, `definirConsulta` injeta um PGlite em memória de `banco-teste.ts`), esquema em `lib/servidor/esquema.ts`. Sessão em cookie JWT (`jose`, 7 dias, `lib/servidor/sessao.ts`), senhas em scrypt (`senha.ts`). `lib/servidor/protecao.ts` é o ponto único de acesso das rotas de API: `exigirUsuario`/`exigirAdmin` conferem o cookie **e** a conta ativa no banco a cada chamada (desativar vale na hora); `proxy.ts` só redireciona páginas para `/login`. Todo acesso a croqui filtra pelo dono (`croquis.ts`; admin é a exceção). O `WizardProvider` tem `salvarAgora()` (fila serializada; chamado em cada "Próximo" do Pedido em diante e no botão Salvar do Resultado; nunca bloqueia a navegação) e `croquiId` no estado. Telas: `/login`, `/criar/croquis` (Meus croquis), `/admin` (contas e limpeza). Limpeza: `lib/servidor/limpeza.ts` + cron diário (`vercel.json` → `/api/limpeza`, protegido por `CRON_SECRET`). Primeira conta admin: `npx tsx --env-file=.env.local scripts/preparar-banco.ts`. Variáveis: `DATABASE_URL`, `SESSAO_SEGREDO`, `CRON_SECRET`, `ADMIN_USUARIO`/`ADMIN_SENHA` (só no script). Desenho completo em `docs/superpowers/specs/2026-11-20-login-persistencia-design.md`.
- **Geração de imagem**: rota `app/api/gerar-imagem/route.ts` (exige login; chave `GEMINI_API_KEY`; ver README). O prompt é montado em `lib/prompt-imagem.ts` e o provedor fica em `lib/servidor/gemini.ts`. O laboratório de prompts (`laboratorio-imagens/`, OpenAI) é bancada de experimento fora do app.

## Convenções

- Nomes de variáveis, funções e componentes em português (refletindo o domínio do negócio), como no restante do projeto.
- Toda medida usa o padrão brasileiro de formatação (`0,000`, vírgula decimal) via `lib/formatacao.ts` — nunca formatar número diretamente num componente.
- No desenho editável, o `html2canvas` só exporta bem anotações em SVG (texto, linhas, setas e retângulos) e a imagem como `<img>` posicionado em %; evite `position: absolute` com `right`/`bottom`/`calc()` e HTML dentro de `foreignObject`.
- `DocumentoCroqui` nunca reage ao tema claro/escuro da interface — sempre renderiza com a paleta fixa vermelho/branco/grafite da Madel.
